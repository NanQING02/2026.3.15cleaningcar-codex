## Summary

本轮最终落地成两部分：

- 清理策略
  - 已接入主流程
  - 当前覆盖截图与单车视频
- 服务化与脚本收口
  - 根目录脚本已收口为 4 个
  - `systemd` 服务只负责 Web，不自动启动推理

关于“人工停止不重启”的口径，当前统一为：

- 手工模式：`./start_web_server.sh stop`
- `systemd` 模式：`systemctl stop cleaningcar-web`
- 上述两种都视为人工停止，不自动重启
- 裸 `kill` / `kill -9` Web 主进程仍视为异常退出，允许 `systemd` 拉起

## 1. 清理策略落地结果

落点文件：

- `cleaningcar/storage_cleanup.py`
- `cleaningcar/pipeline.py`
- `config_manager.py`

当前覆盖范围：

- `captures/<配置名>/`
- `captures/startup/`
- `captures/manual/`
- `video_result/per_id/`

当前规则：

- 周期调度复用 `storage.clean_interval_seconds`
- 每轮按“先删超天数，再删超数量”执行
- 删除顺序固定为最旧文件优先
- `captures/startup/` 与 `captures/manual/` 额外保留最新 1 次
- 清理失败只记 warning，不影响主检测链路

当前配置项：

- `storage.capture_keep_days = 30`
- `storage.capture_keep_count = 3000`
- `storage.per_id_video_keep_days = 15`
- `storage.per_id_video_keep_count = 500`

## 2. 服务化与脚本收口结果

当前根目录只保留 4 个脚本：

- `install_runtime_venv.sh`
  - 只负责安装环境
- `start_web_server.sh`
  - 只负责手工管理 Web
  - 支持 `start|stop|restart|status`
- `uninstall_runtime_venv.sh`
  - 负责卸载环境，并移除 `cleaningcar-web.service`
- `install_cleaningcar_systemd.sh`
  - 负责安装并启用 `cleaningcar-web.service`

`systemd` 交付口径：

- unit 名称：`cleaningcar-web.service`
- 模板文件：`systemd/cleaningcar-web.service`
- `ExecStart` 直接调用 `venv-gst/bin/python -m web.server`
- `Restart=on-failure`
- 开机启用 Web 服务，但不自动拉起推理
- 安装服务前会先停止当前手工 Web，避免端口冲突

## 3. 当前回归点

### 清理策略

- 构造超期截图、超期单车视频，确认会被删除
- 构造未超天数但超数量的文件，确认按最旧优先删除
- `captures/startup/` 与 `captures/manual/` 始终保留最新 1 次
- 清理异常时，主流程、截图、事件、单车视频继续运行

### 服务化

- `./install_runtime_venv.sh` 执行后不自动启动 Web
- `./start_web_server.sh start|stop|restart|status` 手工模式正常
- `./install_cleaningcar_systemd.sh` 安装后，`systemctl status cleaningcar-web` 正常
- `systemctl stop cleaningcar-web` 后保持停止，不自动重启
- 直接杀掉 Web 主进程后，`systemd` 自动重启

- 当前不提供单独的“卸载 systemd 但保留 venv”脚本
- 当前不做多实例 `systemd` 模板扩展
