# 甲方RK3588板端多媒体环境资源提供清单

本文档用于直接向板卡厂商/BSP 供应方提出资源交付要求。

目标很明确：

- 当前项目需要在 RK3588 板端优先启用 `FFmpeg rkmpp` 硬件编解码，并保留 `GStreamer+mpp` 作为第二备选硬解链路
- 请厂商直接提供与当前板端环境匹配的多媒体资源
- 本文档不展开技术分析，只明确需要交付什么、交付到什么程度、如何验收

## 1. 当前板端环境信息

请厂商按以下环境匹配资源：

- 平台：`RK3588`
- 架构：`aarch64`
- 系统：`Ubuntu 20.04.6 LTS`
- 内核：`Linux 5.10.226`
- GStreamer：`1.16.3`
- 当前已装 MPP 运行库版本：`librockchip-mpp1 1.5.0-1`

厂商提供的资源必须明确说明是否适配以上版本组合。

## 2. 厂商必须提供的资源

以下内容为必须项。

### 2.1 `FFmpeg rkmpp` 资源

请提供与当前板端环境匹配、支持 `rkmpp` 的 `ffmpeg` 资源，安装后至少应满足：

- `ffmpeg -hide_banner -decoders | grep rkmpp` 能搜到可用解码器
- `ffmpeg -hide_banner -encoders | grep -E "rkmpp|v4l2m2m|omx"` 至少能搜到一个项目可用的 H.264 编码器，优先 `h264_rkmpp`
- 项目可优先命中 `FFmpeg` 硬解/硬编链路

交付形式任选其一：

- 完整板端镜像
- 完整 rootfs / BSP 多媒体增量包
- 完整 deb 安装包集合

不接受只给一个零散 `.so` 文件。

### 2.2 Rockchip GStreamer MPP 插件包

请同时提供与当前板端环境匹配的 Rockchip GStreamer MPP 插件资源，作为第二备选硬解链路。安装后至少应满足：

- 系统可识别 `mppvideodec`
- GStreamer 插件目录内存在 `libgstrockchipmpp.so` 或功能等价插件文件
- 本地 H.264 文件可通过 `GStreamer+mpp` 跑通硬解

### 2.3 依赖资源

请同时提供上述两套链路所需的全部依赖资源，包括但不限于：

- 对应版本的 Rockchip MPP 运行库
- 对应版本的 FFmpeg 依赖库
- 对应版本的 GStreamer 依赖库
- 必要的配置文件
- 必要的软链接或安装后处理步骤

要求安装完成后可直接使用，不需要现场再手工补链路或猜依赖。

### 2.4 安装说明

请提供完整安装说明，至少包括：

- 资源包名称
- 资源包版本
- 适配的系统版本
- 适配的 BSP 版本
- 安装命令
- 安装后是否需要重启
- 安装后验证命令

### 2.5 版本对应关系说明

请书面说明以下版本对应关系：

- 板卡型号
- BSP 版本
- 内核版本
- Ubuntu 版本
- FFmpeg 版本
- GStreamer 版本
- Rockchip MPP 版本
- GStreamer Rockchip 插件版本

要求厂商明确承诺：本次交付资源与上述版本组合兼容。

## 3. 建议厂商一并提供的资源

以下内容建议一并提供，避免后续再次补环境。

### 3.1 版本边界说明

如果当前版本无法同时提供 `FFmpeg rkmpp` 和 Rockchip GStreamer MPP 插件，请厂商明确书面说明“不支持”的具体项和原因，不要让现场继续反复排查。

### 3.2 最小验证样例

建议厂商一并提供：

- 一份最小测试视频
- 一份最小验证命令

这样现场可以快速确认资源是否真正生效。

## 4. 厂商交付后的验收标准

厂商交付完成后，至少要满足以下验收结果。

### 4.1 `FFmpeg rkmpp` 验收

执行：

```bash
ffmpeg -hide_banner -decoders | grep rkmpp
ffmpeg -hide_banner -encoders | grep -E "rkmpp|v4l2m2m|omx"
```

验收要求：

- 解码器列表能看到 `rkmpp` 相关项
- 编码器列表至少能看到一个项目可用的 H.264 编码器，优先 `h264_rkmpp`

### 4.2 GStreamer 插件验收

执行：

```bash
gst-inspect-1.0 mppvideodec
```

验收要求：

- 命令必须成功
- 不能再出现 `No such element or plugin 'mppvideodec'`

### 4.3 插件文件验收

执行：

```bash
find /usr/lib /usr/lib/aarch64-linux-gnu /usr/local/lib -path "*gstreamer-1.0*" -type f | grep -Ei "rockchip|mpp"
```

验收要求：

- 能找到 `libgstrockchipmpp.so` 或功能等价插件文件

### 4.4 最小硬解验收

执行：

```bash
gst-launch-1.0 -v \
  filesrc location="/home/hinlink/视频/黑夜.mp4" ! \
  qtdemux ! h264parse ! mppvideodec ! \
  videoconvert ! fpsdisplaysink video-sink=fakesink sync=false
```

验收要求：

- 管线必须可以启动
- 不能再报 `no element "mppvideodec"`
- 必须能正常跑完或持续输出 FPS

### 4.5 项目实际启用验收

项目启用：

```json
"video": {
  "hw_decode": true
}
```

项目日志必须出现以下任一内容：

- `[reader] Using FFmpeg hardware decoder ...`
- `[reader] Using GStreamer+mpp file pipeline for ...`
- `[reader] Using GStreamer+mpp RTSP TCP pipeline for ...`

若未出现，视为厂商交付资源仍未满足项目实际使用要求。

为避免现场重复排查，本次不接受以下交付方式：

- 只回复“环境支持 mpp”但不提供安装资源

- 不说明适配的系统/BSP 版本
- 不提供安装说明和验收方法

## 7. 可直接发给厂商的简版需求

> 请按当前甲方 RK3588 板端环境提供与 `Ubuntu 20.04.6 + Linux 5.10.226 + GStreamer 1.16.3 + aarch64` 匹配的 `FFmpeg rkmpp` 资源和 Rockchip GStreamer MPP 插件资源。安装后必须能让项目优先命中 `FFmpeg` 硬解/硬编，并在缺少 `FFmpeg` 命中时可退到 `mppvideodec`。请确保 `ffmpeg -hide_banner -decoders | grep rkmpp`、`ffmpeg -hide_banner -encoders | grep -E "rkmpp|v4l2m2m|omx"`、`gst-inspect-1.0 mppvideodec` 和 `gst-launch-1.0 ... ! mppvideodec ! ...` 都能通过，并同时提供完整依赖、安装说明和版本对应关系。仅回复“环境支持”或只给零散 `.so` 文件，不视为完成交付。
