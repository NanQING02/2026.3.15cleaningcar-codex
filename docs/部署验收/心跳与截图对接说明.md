# 心跳与截图对接说明

本文面向甲方对接、板端部署和联调人员，说明当前项目里的：

- 心跳文件如何产生、如何读取、如何判活
- 手动截图命令如何下发、如何出结果、如何取图
- 在不同设备部署时，如何使用相对路径配置运行目录

---

## 1. 对接总览

当前项目里有两套运行期协作机制：

### 1.1 心跳机制

- 推理主进程周期性写一个心跳 JSON 文件
- Web/guardian 读取这个心跳文件，判断推理是否健康
- 如果心跳异常，guardian 会自动拉起或重启推理进程

### 1.2 截图机制

- Web 接口或外部程序先写一个命令文件到命令目录
- 推理主循环轮询命令目录，识别到截图命令后保存截图
- 保存成功后写 `*.done.json`
- 保存失败后写 `*.failed.json`

这意味着：

- **心跳推荐通过 Web 健康接口读取**
- **截图推荐通过 Web 接口下发**
- **如果甲方程序和设备在同一台机器，也可以直接读写命令/结果文件**

## 2. 路径口径

### 2.1 相对路径解析规则

运行时路径如果写成相对路径，当前代码会按 **配置文件所在目录** 解析。

例如当前常见启动方式是：

- 配置文件：`configs/config.json`

那么：

- `captures/manual` 实际会解析到 `configs/captures/manual`
- `../captures/manual` 实际会解析到 `captures/manual`

因此，如果项目在不同设备上的部署根目录不一样，**建议在配置里使用“相对 `configs/` 的路径”**，不要写设备专属绝对路径。

### 2.2 推荐配置写法

如果希望运行产物都落在项目根目录下，建议在 `configs/config.json` 里这样写：

```json
{
  "system": {
    "command_dir": "../runtime/cmd",
    "heartbeat_path": "../runtime/status/cleaningcar_heartbeat.json",
    "startup_flag_path": "../runtime/status/cleaningcar_started.flag",
    "startup_capture_dir": "../captures/startup",
    "manual_capture_dir": "../captures/manual"
  }
}
```

按 `configs/config.json` 解析后，实际对应：

- 命令目录：`runtime/cmd`
- 心跳文件：`runtime/status/cleaningcar_heartbeat.json`
- 启动标志：`runtime/status/cleaningcar_started.flag`
- 启动截图：`captures/startup`
- 手动截图：`captures/manual`

如果配置文件将来不放在 `configs/` 下，仍然遵循同一规则：**相对路径永远相对配置文件所在目录**。

## 3. 心跳对接说明

### 3.1 心跳文件作用

心跳文件用于表示推理进程是否还活着、是否还在持续推进。

心跳里至少会包含这些核心字段：

- `timestamp`
  - 最近一次写心跳的时间戳
- `pid`
  - 当前推理进程 PID
- `status`
  - 当前状态，如 `starting`、`running`、`waiting_reader`、`backpressure`、`stopping`
- `last_progress_ts`
  - 最近一次真正推进处理流程的时间
- `latest_frame_idx`
  - 最近处理到的帧号
- `config_name`
  - 当前使用的配置名
- `source`
  - 当前视频源

典型结构如下：

```json
{
  "timestamp": 1760000000.123,
  "pid": 12345,
  "status": "running",
  "last_progress_ts": 1760000000.023,
  "latest_frame_idx": 18234,
  "config_name": "config.json",
  "source": "rtsp://xxx/stream"
}
```

### 3.2 甲方推荐读取方式

推荐甲方不要直接解析心跳文件，而是直接调用 Web 健康接口：

- `GET /inference/health`

示例：

```bash
curl "http://<设备IP>:8000/inference/health"
```

典型返回字段：

- `running`
  - 当前推理进程是否在运行
- `pid`
  - 当前推理 PID
- `heartbeat.available`
  - 是否读到了心跳文件
- `heartbeat.healthy`
  - 当前心跳是否健康
- `heartbeat.reason`
  - 判定原因

甲方通常只要关心这两个判断：

- `running == true`
- `heartbeat.healthy == true`

### 3.3 `heartbeat.reason` 常见值

- `ok`
  - 正常
- `starting`
  - 启动宽限期内，暂不判故障
- `not_started`
  - 还没启动推理
- `heartbeat_missing`
  - 没找到心跳文件
- `heartbeat_pid_mismatch`
  - 心跳文件不是当前推理进程写的
- `heartbeat_stale`
  - 心跳时间戳过旧
- `heartbeat_timestamp_missing`
  - 心跳文件里没有时间戳
- `progress_stale`
  - 虽然心跳还在写，但流程已经长时间没推进
- `progress_missing`
  - 缺少推进时间字段

### 3.4 甲方轮询建议

- 建议甲方每 `2~5` 秒轮询一次 `GET /inference/health`
- 不建议按更高频率去轮询本地心跳文件
- 如果只做看板展示，`5` 秒一次通常足够
- 如果要做自动故障切换，建议结合 `heartbeat.reason` 做分类处理

## 4. 截图命令对接说明

### 4.1 当前截图机制不是同步接口

`POST /snapshot/keep` 当前只负责**写命令并入队**，不是收到请求后立刻直接返回截图文件。

完整流程如下：

1. 甲方调用 `POST /snapshot/keep`
2. Web 写入一个 `*.cmd.json` 命令文件
3. 推理主循环轮询命令目录
4. 推理进程用当前缓存帧保存图片
5. 写入 `*.done.json` 或 `*.failed.json`
6. 原始 `*.cmd.json` 被删除

### 4.2 Web 下发方式

接口：

- `POST /snapshot/keep`

请求体：

```json
{
  "tag": "party_a",
  "raw": true,
  "annotated": true
}
```

字段说明：

- `tag`
  - 截图标签，会拼到文件名里，建议只用字母、数字、下划线、中划线
- `raw`
  - 是否保存原图
- `annotated`
  - 是否保存带框/带标注图

限制：

- `raw` 和 `annotated` 不能同时为 `false`

调用示例：

```bash
curl -X POST "http://<设备IP>:8000/snapshot/keep" \
  -H "Content-Type: application/json" \
  -d "{\"tag\":\"party_a\",\"raw\":true,\"annotated\":true}"
```

典型返回：

```json
{
  "status": "queued",
  "command_file": "运行时命令文件路径"
}
```

说明：

- `command_file` 是设备上的实际命令文件路径
- 返回 `queued` 只代表命令已经入队
- 不代表截图已经保存成功

### 4.3 结果文件说明

命令处理成功后，会写：

- `*.done.json`

失败时，会写：

- `*.failed.json`

成功结果典型结构：

```json
{
  "status": "done",
  "cmd": "keep_snapshot",
  "frame_idx": 18234,
  "captures": {
    "raw": "captures/manual/20260325/10/20260325_103015_f018234_party_a_raw.jpg",
    "annotated": "captures/manual/20260325/10/20260325_103015_f018234_party_a_annotated.jpg"
  }
}
```

失败结果典型结构：

```json
{
  "status": "failed",
  "reason": "no frame cached yet"
}
```

常见失败原因：

- `no frame cached yet`
  - 推理刚启动，还没有缓存到可截图帧
- `snapshot save failed`
  - 图片保存失败，通常要检查目录权限或磁盘空间
- `raw/annotated cannot both be false`
  - 请求参数不合法

### 4.4 截图文件目录

手动截图默认写入：

- `system.manual_capture_dir`

目录结构为：

- `<manual_capture_dir>/YYYYMMDD/HH/`

文件名格式为：

- `YYYYMMDD_HHMMSS_f<帧号>_<tag>_raw.jpg`
- `YYYYMMDD_HHMMSS_f<帧号>_<tag>_annotated.jpg`

## 5. 甲方推荐对接方案

### 5.1 方案 A：HTTP 对接，推荐

适用场景：

- 甲方系统和板端不是同一台机器
- 甲方希望通过网络统一接入
- 不希望直接访问板端文件系统

推荐做法：

### 心跳

- 调用 `GET /inference/health`
- 以 `running + heartbeat.healthy` 作为是否正常的主判断

### 截图

- 调用 `POST /snapshot/keep` 下发截图请求
- 然后通过以下二选一拿结果：
  - 由板端把 `captures` 目录共享给甲方读取
  - 在现有基础上补一个“按命令文件查询结果”的轻量接口

说明：

- 当前仓库里**已有截图入队接口**
- 当前仓库里**没有现成的截图结果查询接口**
- 如果甲方要求“HTTP 请求后直接拿到图片地址/内容”，建议补一层结果查询接口

### 5.2 方案 B：同机文件对接

适用场景：

- 甲方程序就跑在同一台设备上
- 甲方可以直接访问本地目录

推荐做法：

### 心跳

- 直接读取 `heartbeat_path`
- 或者读取 `GET /inference/health`

### 截图

- 直接向 `command_dir` 写入 `*.cmd.json`
- 再轮询同目录下对应的 `*.done.json` / `*.failed.json`
- 成功后再去 `captures` 目录拿图片

命令文件最小示例：

```json
{
  "cmd": "keep_snapshot",
  "tag": "party_a",
  "raw": true,
  "annotated": true
}
```

命令文件命名要求：

- 后缀必须是 `*.cmd.json`

## 6. 建议给甲方的联调口径

建议直接按下面这套口径对外：

### 6.1 心跳口径

- 甲方无需直接解析推理进程日志
- 甲方优先调用 `GET /inference/health`
- 只要 `running=true` 且 `heartbeat.healthy=true`，就视为设备运行正常

### 6.2 截图口径

- 甲方调用 `POST /snapshot/keep` 发起截图
- 板端异步处理截图
- 成功后生成 JPG 文件和 `*.done.json`
- 失败后生成 `*.failed.json`

### 6.3 路径口径

如果要做跨设备统一部署，建议配置里统一使用下面这组相对路径：

- `system.command_dir = "../runtime/cmd"`
- `system.heartbeat_path = "../runtime/status/cleaningcar_heartbeat.json"`
- `system.startup_flag_path = "../runtime/status/cleaningcar_started.flag"`
- `system.startup_capture_dir = "../captures/startup"`
- `system.manual_capture_dir = "../captures/manual"`

这样无论项目根目录部署在什么位置，只要 `configs/config.json` 的相对结构不变，运行目录就会落到统一位置。

---

## 7. 当前实现的注意事项

- Web 默认无鉴权，联调环境建议仅放内网使用
- 当前允许跨域，若要对外开放，建议前面加网关或鉴权层
- `POST /snapshot/keep` 是异步入队，不是同步返回图片
- `system.api.capture_mode` 影响的是**事件上报截图格式**，不是手动截图命令
- 启动截图属于自动行为，和手动截图命令不是同一条链路

---

## 8. 最简对接清单

如果只保留最小对接内容，可以只给甲方这 4 条：

1. 健康检查接口：`GET /inference/health`
2. 截图下发接口：`POST /snapshot/keep`
3. 推荐相对路径：
   - `../runtime/cmd`
   - `../runtime/status/cleaningcar_heartbeat.json`
   - `../captures/manual`
4. 截图是异步机制，成功后看 `*.done.json` 和截图文件
