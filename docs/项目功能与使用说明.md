# 项目功能与使用说明

## 1. 当前项目具备的功能

### 1.1 主检测链路

- 使用 `models/detection/best.rknn` 进行车辆、水流等目标检测
- 按 `configs/*.json` 中的 ROI、流向、事件规则进行业务判定
- 输出事件 JSON、事件截图、检测 CSV、调试画面

### 1.2 车牌识别链路

- 当前只启用双模型车牌链路
- 车牌检测模型：`models/plate/plate_detect.rknn`
- 车牌识别 / 颜色模型：`models/plate/plate_rec_color.rknn`
- 运行代码位于：
  - `cleaningcar/plate_lpr.py`
  - `cleaningcar/worker.py`

### 1.3 FP 检测后处理切换

检测模型后处理现在支持两种模式，由 `video.fp_output_mode` 控制：

- `6`
  - 默认模式
  - 即使模型给出 `9` 个输出，也只使用每个尺度的 `box + class`
  - 适合和旧链路做稳定对比
- `9`
  - 使用每个尺度的 `box + class + score`
  - 适合和完整 9 输出解析方式对比

命令行可以临时覆盖：

```bash
python run_zone_detect.py --config configs/config.json --fp_output_mode 6
python run_zone_detect.py --config configs/config.json --fp_output_mode 9
```

### 1.4 Web 管理能力

- Web 首页：ROI 和配置管理
- 推理启动、停止、重启
- 推理状态、健康状态和日志查看
- 调试帧查看
- 事件日志查看
- 单车视频列表查看

### 1.5 运行保障能力

- guardian 守护推理进程
- 基于心跳和进度时间戳判断“真卡死”
- 卡死后自动拉起推理

### 1.6 启动信号

- 启动成功后写日志 `[startup-signal]`
- 写入启动标志文件
- 自动保存启动截图

### 1.7 手动保留截图

- 外部程序可通过命令目录投递截图命令
- Web 可通过接口投递截图命令
- 支持保留原图和标注图

## 2. 目录结构说明

- `cleaningcar/`
  - 主运行代码
- `web/`
  - FastAPI Web 管理层和推理 guardian
- `configs/`
  - 运行配置
- `models/`
  - 当前实际使用的 RKNN 模型
- `future_modules/`
  - 保留但当前未启用 / 后续开发模块
- `packages/`
  - RKNN / RGA 运行依赖
- `docs/`
  - 项目说明、方案、整理记录

## 3. 当前模型与主入口

### 3.1 当前实际运行模型

```text
models/detection/best.rknn
models/plate/plate_detect.rknn
models/plate/plate_rec_color.rknn
```

### 3.2 主入口

- 检测主程序：`run_zone_detect.py`
- Web 服务：`python -m web.server`

## 4. 运行前准备

### 4.1 将整个项目目录复制到 RKNN 板端

建议放到类似路径：

```bash
/home/hinlink/2026.3.15cleaningcar-codex
```

### 4.2 确认模型存在

```bash
ls models/detection/best.rknn
ls models/plate/plate_detect.rknn
ls models/plate/plate_rec_color.rknn
```

### 4.3 确认配置文件

- 默认配置：`configs/config.json`
- 备用配置：`configs/config_绕行.json`

## 5. 启动方式

### 5.1 推荐方式：脚本启动 Web 与 guardian

```bash
chmod +x install_runtime_venv.sh
./install_runtime_venv.sh
```

### 5.2 手动启动 Web

```bash
source venv-gst/bin/activate
python -m web.server --config configs/config.json --host 0.0.0.0 --port 8000
```

### 5.3 直接启动检测主程序

```bash
source venv-gst/bin/activate
python run_zone_detect.py --config configs/config.json
```

切换检测后处理模式：

```bash
python run_zone_detect.py --config configs/config.json --fp_output_mode 6
python run_zone_detect.py --config configs/config.json --fp_output_mode 9
```

## 6. 运行输出位置

- 事件 JSON：`events/<配置名>/`
- 事件截图：`captures/<配置名>/`
- 推理日志：`logs/inference/`
- Web 启动日志：`web_server_8000.log`
- 调试帧：由 `video.debug_frame_path` 控制
- 启动截图：由 `system.startup_capture_dir` 控制
- 手动截图：由 `system.manual_capture_dir` 控制
- 心跳文件：由 `system.heartbeat_path` 控制
- 启动标志：由 `system.startup_flag_path` 控制
- 命令目录：由 `system.command_dir` 控制

## 7. Web 接口使用

### 常用接口

- `GET /`
- `POST /inference/start`
- `POST /inference/stop`
- `POST /inference/restart`
- `GET /inference/status`
- `GET /inference/health`
- `POST /snapshot/keep`

### 手动截图接口示例

```bash
curl -X POST "http://127.0.0.1:8000/snapshot/keep" \
  -H "Content-Type: application/json" \
  -d "{\"tag\":\"manual\",\"raw\":true,\"annotated\":true}"
```

## 8. 建议板端验证顺序

1. 先启动 Web，确认 `http://<设备IP>:8000/` 可访问
2. 查看 `/inference/status`，确认推理被 guardian 拉起
3. 等待出现 `[startup-signal]`
4. 检查启动标志文件和启动截图
5. 调用 `/snapshot/keep`，检查手动截图
6. 在 `6` 和 `9` 两种后处理模式之间切换对比效果
