# 项目整理报告

## 本次整理目标

- 保留现有功能不变，只整理运行链路、脚本入口和文档结构
- 明确主运行路径只保留当前真正使用的模型和代码
- 让板端交付时一眼能看清“哪些是运行必须项，哪些是历史保留项”

## 当前主运行链路

- 检测模型：`models/detection/best.rknn`
- 车牌双模型：`models/plate/plate_detect.rknn` + `models/plate/plate_rec_color.rknn`
- 默认配置目录：`configs/`
- 主程序入口：`run_zone_detect.py`
- 主代码目录：`cleaningcar/`
- Web 管理目录：`web/`

## 本轮整理结果

### 1. 根目录脚本收口为 4 个

当前根目录只保留：

- `install_runtime_venv.sh`
- `start_web_server.sh`
- `uninstall_runtime_venv.sh`
- `install_cleaningcar_systemd.sh`

收口结果：

- 安装、手工启动、卸载、服务化四类入口明确分开
- 不再保留额外的 `stop_*.sh`、`run_*.sh`、`setup_*.sh` 脚本
- 手工停启统一走 `start_web_server.sh` 的动作参数

### 2. 模型与功能口径收口

- 检测主模型固定为 `models/detection/best.rknn`
- 车牌链路只保留双模型方案
- 旧单模型 LPR 只留在 `future_modules/legacy_lpr/` 作为历史资料
- `video.fp_output_mode` 允许对同一检测模型做 `6/9` 两种后处理切换

### 3. 运行产物目录收口

- 事件 JSON：`events/<配置名>/`
- 事件截图：`captures/<配置名>/`
- 启动截图：`captures/startup/`
- 手动截图：`captures/manual/`
- 单车视频：`video_result/per_id/`
- 推理日志：`logs/inference/`

### 4. 文档分类收口

当前 `docs/` 已分为：

- `docs/总览说明/`
- `docs/部署验收/`
- `docs/规划记录/`

### 5. 代码结构继续保持解耦

- `cleaningcar/storage_cleanup.py` 独立负责运行产物清理
- `cleaningcar/text_render.py` 独立负责中文渲染
- `cleaningcar/plate_lpr.py` 负责双模型车牌推理
- `cleaningcar/plate.py` 只负责车牌文本后处理与锁定

## 当前目录语义

- `cleaningcar/`
  - 当前实际运行的检测、跟踪、事件与视频处理代码
- `models/`
  - 当前实际运行模型
- `configs/`
  - 当前实际运行配置文件
- `fonts/`
  - 中文渲染使用的项目内置字体
- `future_modules/`
  - 未启用模块、历史实现、后续开发保留内容
- `packages/`
  - RKNN / RGA 运行依赖
- `docs/`
  - 项目说明、实施记录、部署验收文档

## 当前整理结论

- 运行入口已经从“多个零散脚本”收口成 4 个明确入口
- 运行代码、模型、配置、文档的边界已经清晰
- 文档入口已经只保留一套主路径，不再保留重复兼容文档
- 板端交付时，只需要重点关注 `configs/`、`models/`、`fonts/`、`packages/`、四个根目录脚本和 `cleaningcar/` / `web/`
