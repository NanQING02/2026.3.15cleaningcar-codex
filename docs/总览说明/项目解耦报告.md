# 项目解耦报告

## 目标

在不改变现有功能、入口方式、配置结构、HTTP 路由和事件输出行为的前提下，将原先集中在大文件中的逻辑拆分为职责清晰的模块，便于维护、扩展和部署。

## 当前解耦结果

### 1. 检测主链路拆分到 `cleaningcar/`

主运行代码已经拆成独立模块：

- `cleaningcar/constants.py`
  - 全局常量、类别定义、阈值和标签映射
- `cleaningcar/runtime_config.py`
  - 配置加载、默认配置路径、CLI 覆盖
- `cleaningcar/video_io.py`
  - 视频源打开、运行时路径解析、FFmpeg 写出
- `cleaningcar/vision.py`
  - ROI 缩放、几何辅助、IoU 计算
- `cleaningcar/plate.py`
  - 车牌文本规范化和跟踪
- `cleaningcar/tracking.py`
  - 车辆跟踪
- `cleaningcar/events.py`
  - 事件状态机、截图输出、上报封装
- `cleaningcar/worker.py`
  - RKNN 检测 worker 和双模型车牌识别
- `cleaningcar/fp_detect.py`
  - FP 检测模型后处理
- `cleaningcar/runtime_signals.py`
  - 心跳、启动信号、命令目录截图
- `cleaningcar/pipeline.py`
  - 主流程编排和结果汇总
- `cleaningcar/cli.py`
  - 命令行参数与启动装配

### 2. Web 控制层拆分到 `web/`

- `web/state.py`
  - Web 运行状态、默认路径和缓存
- `web/models.py`
  - Web 请求模型
- `web/inference.py`
  - 推理 guardian、自启、健康检测、日志缓存
- `web/helpers.py`
  - 配置读取、路径解析、日志和调试帧读取
- `web/server.py`
  - FastAPI 路由和应用装配

## 本轮新增解耦点

### FP 检测后处理策略解耦

检测模型后处理不再写死成单一路径，而是通过独立配置项切换：

- `video.fp_output_mode=6`
  - 默认模式
  - 9 输出模型也按 `box + class` 方式解析
- `video.fp_output_mode=9`
  - 使用 `box + class + score`

这样做的结果：

- 模型输出结构和业务主流程进一步解耦
- 同一个 `best.rknn` 可以在两种解析方式之间一键切换
- 便于排查模型输出差异和做效果对比

### 运行信号解耦

运行期信号和主业务流程也已拆分：

- 心跳：`cleaningcar/runtime_signals.py`
- 启动信号：`cleaningcar/runtime_signals.py`
- 手动截图命令：`cleaningcar/runtime_signals.py`
- 健康检测与自启：`web/inference.py`

## 解耦收益

- 主入口已经收口为装配层
- 检测、后处理、车牌识别、事件、守护和 Web 职责已经分开
- 检测模型的 6/9 输出解析切换不再需要改主流程
- 后续继续做脚本拆分、systemd 化、多配置管理时，改动面会更小
