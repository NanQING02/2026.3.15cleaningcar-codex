# 项目功能与使用说明

## 1. 当前项目具备的功能

### 1.1 主检测链路

- 使用 `models/detection/best.rknn` 做车辆、清洗相关目标检测
- 当 `video.hw_decode=true` 时，读流顺序为 `FFmpeg 硬解 -> GStreamer+mpp 硬解 -> 软件解码`
- 按 `configs/*.json` 中的 ROI、流向和业务规则做事件判定
- 输出事件 JSON、事件截图、检测 CSV 和调试画面

### 1.2 车牌识别链路

- 当前只启用双模型车牌链路
- 车牌检测模型：`models/plate/plate_detect.rknn`
- 车牌识别/颜色模型：`models/plate/plate_rec_color.rknn`
- `cleaningcar/plate_lpr.py` 负责双模型推理
- `cleaningcar/plate.py` 只负责文本规范化、合法性校验和锁定

### 1.3 中文显示与截图

- `cleaningcar/text_render.py` 统一负责中文渲染
- 字体固定优先读取 `fonts/platech.ttf`
- 事件截图只有真实落盘成功时，事件 JSON 才写入 `captureImage`
- 启动截图写入 `captures/startup/`
- 手动保留截图写入 `captures/manual/`

### 1.4 运行保障

- guardian 负责守护推理进程
- 基于心跳和进度判断真卡死
- 异常时自动拉起推理进程
- 启动成功后写日志 `[startup-signal]` 并生成启动标志文件

### 1.5 单车视频与清理策略

- 当前只保留 per-id 单车视频，不再提供全局视频保存功能
- 单车视频写出顺序为 `FFmpeg 硬编 -> GStreamer 硬编 -> FFmpeg libx264`
- 单车视频目录由 `logic.per_id_video_dir` 控制
- 留空、空白、不可写时统一回退到 `video_result/per_id/`
- 截图与单车视频已接入周期清理
- 清理规则固定为先按天数、再按数量
- `captures/startup/` 与 `captures/manual/` 额外保留最新 1 次

### 1.6 本地文件视频运行策略

- 本地文件视频默认只跑一遍
- 读到 EOF 后退出本次推理
- 只有手动勾选自动重启后，文件源才会重新循环
- Web 面板点击“停止”不会改写当前自动重启勾选状态

## 2. 当前目录结构

- `cleaningcar/`
  - 主运行包
- `web/`
  - FastAPI 管理层与 guardian
- `configs/`
  - 运行配置
- `models/`
  - 当前使用的 RKNN 模型
- `fonts/`
  - 项目内置字体目录
- `future_modules/`
  - 预留但当前未启用模块
- `packages/`
  - RKNN / RGA 运行依赖
- `docs/`
  - 项目说明与部署验收文档

## 3. 根目录四个脚本

### `install_runtime_venv.sh`

- 安装或重建 `venv-gst/`
- 安装系统依赖、Python 依赖、RKNN/RGA 运行库
- 只安装环境，不启动 Web

### `start_web_server.sh`

- 手工管理 Web 服务
- 支持 `start|stop|restart|status`
- 后台启动时会输出 `web_server_<port>.pid` 与 `web_server_<port>.log`

### `uninstall_runtime_venv.sh`

- 停止手工 Web
- 删除 `venv-gst/`
- 若已安装 `cleaningcar-web.service`，会一并停用并移除

### `install_cleaningcar_systemd.sh`

- 安装并启用 `cleaningcar-web.service`
- 安装前会先停止手工 Web
- 开机只启动 Web，不自动启动推理

## 4. 常用启动方式

### 4.1 安装运行环境

```bash
chmod +x install_runtime_venv.sh
./install_runtime_venv.sh
```

### 4.2 手工启动 Web

`./start_web_server.sh` 会直接使用 `venv-gst/bin/python`，所以安装完环境后可以直接运行脚本，不强制先激活虚拟环境。

如果你后面还要手工执行 `python -m web.server`、`python run_zone_detect.py`、`pip` 等命令，再先激活虚拟环境更方便。

```bash
chmod +x start_web_server.sh
./start_web_server.sh start
```

其他常用动作：

```bash
./start_web_server.sh status
./start_web_server.sh restart
./start_web_server.sh stop
```

### 4.3 `systemd` 开机自启 Web

```bash
chmod +x install_cleaningcar_systemd.sh
./install_cleaningcar_systemd.sh
systemctl status cleaningcar-web --no-pager
```

说明：

- `systemctl stop cleaningcar-web` 属于人工停止，不会自动重启
- 直接 `kill` / `kill -9` Web 主进程会被 `systemd` 视为异常退出并拉起

### 4.4 卸载运行环境

```bash
chmod +x uninstall_runtime_venv.sh
./uninstall_runtime_venv.sh
```

### 4.5 直接启动主程序

```bash
source venv-gst/bin/activate
python run_zone_detect.py --config configs/config.json
```

### 4.6 切换 FP 后处理模式

```bash
python run_zone_detect.py --config configs/config.json --fp_output_mode 6
python run_zone_detect.py --config configs/config.json --fp_output_mode 9
```

## 5. 关键输出位置

- 事件 JSON：`events/<配置名>/`
- 事件截图：`captures/<配置名>/`
- 启动截图：`captures/startup/`
- 手动截图：`captures/manual/`
- 单车视频：`video_result/per_id/`
- 推理日志：`logs/inference/`
- Web 日志：`web_server_8000.log`
- Web pid 文件：`web_server_8000.pid`
- 心跳文件：由 `system.heartbeat_path` 控制
- 启动标志：由 `system.startup_flag_path` 控制
- 命令目录：由 `system.command_dir` 控制

## 6. 板端部署提醒

- 部署时必须带上 `fonts/platech.ttf`
- `requirements.txt` 已包含 `Pillow`
- 手工停 Web 请使用 `./start_web_server.sh stop`
- `systemd` 人工停服务请使用 `systemctl stop cleaningcar-web`
- 若板端缺少 `ffmpeg rkmpp`，程序会退到 `GStreamer+mpp`；若 `mppvideodec` 也缺失，再退到软件解码
- 当前只保留双模型车牌链路，不再验旧单模型 LPR
- 验收时应同时检查：
  - `/inference/health` 保持 `ok`
  - `restart_count` 不增长
  - 心跳持续更新
  - 事件 JSON 正常生成
  - `captureImage` 非空且文件真实存在
  - 中文标签显示正常
